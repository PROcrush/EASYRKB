# EASYRKB 自动 Cue：集成约定

2026-10-12，用户明确要求：本功能最终集成在 EASYRKB 内；先由用户确认网格，再自动标注 Cue。当前为集成设计，应用入口、IPC 与原生候选算法尚未接入。

## 用户流程

1. 在 EASYRKB 中选中歌曲，在现有播放器检查/校正网格。
2. 确认开头、中部、尾部的鼓点对齐，以及小节首拍；未确认的歌曲不能生成自动 Cue。
3. 点击“自动标注 Cue”，预览混入、段落变化、混出候选；可以试听、取消或调整候选。
4. 应用所选候选到本歌曲，再沿用现有曲库保存与 USB 导出流程。

最终流程直接使用应用中当前的网格，不要求用户另开网页、配置 Python 或通过 XML 来回交换。开发期间的独立 Python/网页仍作为算法测试工具。

首版针对 House / Techno；频谱/能量变化只标为候选，不能自动等同 Drop、人声入口或副歌。默认最多 A–H 八个 Hot Cue、十个 Memory Cue；保留混出空间，不为填满槽位添加低置信候选。

## 已核查的现有接口

| 范围 | 当前源码 | 集成用途 |
|---|---|---|
| 网格编辑 | `src/views/player/useGridEditor.ts`、`src-tauri/src/grid.rs` | 复用现有平移、BPM、小节首拍等校正操作 |
| 网格读取/更新 | `src/views/player/useTrackGrid.ts`、`src/ipc/types.ts` 的 `gridState` / `onGridChanged` | 读取当前歌曲实际拍点；网格修改时使确认与候选失效 |
| Cue 写入 | `src-tauri/src/cues.rs`、`rbl-db` Writer | 通过已有写入保护、备份、索引刷新和 `cues:changed` 更新界面 |
| 本机音频分析 | `crates/rbl-analysis/`、`src-tauri/src/analysis.rs` | 在阻塞工作线程上运行独立候选检测，复用解码能力 |
| 分析设置 | `src/views/analysis/AnalysisDialog.tsx` | 保留现有 BPM/KEY 分析流程；自动 Cue 作为网格确认后的独立操作 |

`crates/rbl-analysis/src/phrase.rs` 目前返回 `None`，并未实现乐句检测。不能把当前代码当成已经具备官方乐句或 Intelligent Cue Creation 能力。新候选模块与该占位实现保持区别，不写入虚构 PSSI。

## 确认与候选的有效性

- 确认绑定当前曲库身份、Track ID 和网格版本；网格版本至少覆盖每个拍点的时间、拍编号、BPM 和曲目时长。
- 网格编辑、重新分析、更换曲库或重新载入了不同网格后，旧确认与旧候选失效，须再次确认。
- 预览携带生成时的网格版本。应用候选前，后端在写入边界重新核对当前版本，防止生成期间或预览期间网格变化造成错位。
- 不把“有 BPM”“分析完成”或“分析锁定”等同于人工确认。确认记录仅代表用户核对，不能宣称算法已证明准确。
- Cue 最终按当前实际拍时间生成，不使用 `first-beat = 0` 的隐式假设；变速曲目不能仅靠一个 AverageBpm 计算全曲位置。

## 保存与撤销要求

- 预览阶段只读取歌曲、网格与已有 Cue；点击应用后才写入。
- 已有手工 Hot Cue、Memory Cue、Loop、注释与颜色默认保留，仅使用空槽并去重。
- 应用后记录本批新增 Cue 的 ID 和生成所用网格版本；撤销/重新生成只针对本批标记。不能通过名称相似来猜测并删除手工 Cue。
- 网格改变不会静默移动手工 Cue；本批自动候选需重新生成或经用户明确选择后调整。
- 新增批量应用接口，应使用实际的批量事务与恢复流程；不能循环调用前端 `addCue` 就宣称整批写入原子完成。
- 延续现有真实曲库写入保护及备份机制，界面通过既有事件刷新；不添加轮询或全曲库隐式后台扫描。

## 拟增加的模块和 IPC（尚未实现）

- `crates/rbl-analysis/src/auto_cue.rs`：独立候选分析，输入音频特征与已确认拍网格，返回候选与依据。
- `src-tauri/src/auto_cue.rs`：确认状态、后台生成、版本校验、批量应用与撤销。
- `src/ipc/`：类型化确认/生成/应用接口及相应 mock，沿用应用现有组织方式。
- `src/views/analysis/AutoCueDialog.tsx`：确认 → 候选试听 → 应用。入口放在所选曲目操作和播放器适当位置。

## 验收边界

需覆盖：未确认不得生成、切歌与换库隔离、网格修改失效、变速拍点、生成/应用期间网格变化、已有 Cue/Loop 保留、满槽与重复位置、取消、失败恢复和本批撤销。测试写入只使用临时曲库与合成音频。

开发原型现已通过 13 项 Python 检查和本机确认页面操作验证；这不表示上述 EASYRKB 集成已实现。真实测试曲《Lost》在 rekordbox XML 浏览器显示了八个 Hot Cue 和十个 Memory Cue，但用户反馈网格固定偏移，正式候选仍待网格校正。最终还需在 EASYRKB 内验证真实曲目确认、生成、应用、重载与导出。
